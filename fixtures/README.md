# fixtures/ — the parity oracle

The TypeScript implementation was the specification for the Rust port, and this
directory is the record of what it did, in a form both languages can read. Every
file here was *generated by a TypeScript test* from the real implementation; the
Rust tests read the same files (`include_str!`, `include_bytes!`) and assert
equality — and only assert. **Rust never writes here.**

## What can still be regenerated, and what is frozen

Twelve of the fifteen families were written by tests in packages that no longer
exist — the runtime they described is Rust now, and deleting the TypeScript
deleted the emitter with it. Those files are **frozen artefacts**: the
specification they record is gone, so there is nothing left to re-derive them
from, and that is the correct end state rather than a gap. They are read by the
Rust tests and by nothing else, and a Rust test that fails against one is a port
that disagrees with the behaviour that shipped — not a fixture to edit.

| Family                                                                                                   | State  |
| -------------------------------------------------------------------------------------------------------- | ------ |
| `protocol/`, `ws/frames/`, `uuid/`                                                                       | live   |
| `config/`, `cron/`, `exec/`, `extension/`, `history/`, `ip/`, `jail/`, `merge/`, `nonce/`, `sqlite/`, `sse/`, `wire/` | frozen |

The three live families come from `packages/protocol`, which is still TypeScript
because the browser parses it. They regenerate the way they always did:

```bash
DARKWIRE_UPDATE_FIXTURES=1 pnpm test
```

`packages/protocol/test/fixtures.test.ts` owns all three. With the variable set it
rewrites its files from the implementation; without it, it reads them and asserts
the implementation still produces exactly those bytes. A change that moves one is
therefore visible in `git diff` as a behaviour change.

## The rename moved two of them

`extension/digest/expected.json` and `vault/envelope.json` were re-derived when the
project was renamed, and the reason is that the rename changed their *inputs* rather
than the behaviour they record. The digest is taken over file names and file bytes, and
the manifest in that tree is now `darkwire.extension.json` holding
`darkwire.extension/1`; the vault's envelope is sealed with the AAD
`darkwire-vault-v1`, which is a different string from the one the recorded ciphertext
was sealed with. A fixture whose input moved and whose output did not is not a record of
anything. Both were regenerated from the implementation in this repository, and they
pin its behaviour from here on.

**Editing a frozen fixture by hand is a last resort and needs a reason in the
commit message.** The whole value of the directory is that nothing in the Rust
workspace can move a file it is asserted against; hand-editing one to make a test
pass converts a parity failure into a silent divergence.

## Shape

Unless a fixture is a single artefact (`config/defaults.json` is the exact file
`saveConfig` writes; `sqlite/seed.db` is a real database), a fixture is

```json
{ "description": "...", "cases": [{ "name": "...", "input": ..., "output": ... }] }
```

serialised with two-space indentation and a trailing newline. A thrown error is
recorded as `{"error": {"kind": ..., "message": ...}}`. The `description` says
what the inputs and outputs mean and names the rules the Rust port has to match.

## Determinism

Nothing here may depend on the machine that generated it. Clocks and random
sources are injected; temp directories are spelled `<root>` and `<base>`; the
process environment is never read. Two exceptions are documented in place:

- `sqlite/seed.db` carries the SQLite version that wrote it in its header, so it
  is not byte-compared. Its `sqlite_master` and rows are dumped beside it
  (`sqlite_master.json`, `seed.json`) and both the file and a freshly built
  database are held to those.
- `extension/digest/tree/` is a committed directory the digest is computed over.
  It assumes a POSIX checkout that preserves symlinks (`link.txt`) and byte-exact
  file contents (`extension/.gitattributes` turns line-ending conversion off); a
  checkout that materialises the symlink computes a different digest. The files
  are `.txt` rather than `.js` because `eslint .` lints every `.js` in the
  repository and this directory has no tsconfig; the digest does not care.

`fixtures/` is in `.prettierignore`: the formatting is the emitter's.
